# KINII v3 — Спецификация синтаксиса

## Миссия языка (не отступаем)

1. **Понятный** — код читается как псевдокод; ошибки компилятора объясняют, где
   ошибка, почему и как исправить.
2. **Удобный** — подсветка в VS Code, быстрая компиляция, минимум церемоний.
3. **Компактный** — компилятор не добавляет от себя ни байта: мёртвый код не
   попадает в бинарник, скрытого рантайма нет, оптимизации не меняют логику.

## Происхождение: объединяем «лучшее из» (решение от октября 2026)

Главный критерий отбора — **понятность и удобство одновременно**. Не «псевдокод», а
язык, в котором опытный человек решает задачу в 3–4 строки то, что новичок напишет
в 10–20, — и решение остаётся самоочевидным при чтении. Компактность достигается
выразительными конструкциями (comprehension, decide/weight, именованные литералы,
автоматический вывод типов), а не неявной магией: неявные преобразования,
сюрпризные перегрузки операторов, макросы, меняющие смысл кода со стороны, —
всё это осознанно не берём. Мера: «поймёт ли это программист, впервые открывший
файл — без комментария?» Если нет — не добавляем или делаем её явной.

Двухфазный принцип: **ядро маленькое и честное (как Lua/Ядро Линукса), всё богатство — в типах и библиотеке (как C#/Java)**. Мы не копируем языки целиком — берём только их сильные стороны:

| Язык | Берём | В KINII это |
|---|---|---|
| **C++** | нулевая стоимость абстракций; полный контроль типов памяти | `u8..u64/ptr/v_word/cell`, компиляция в чистый C++ без скрытого рантайма; оптимизатор убирает мёртвый код |
| **C# / Java** | видимость внутри проекта без хедеров; богатая стандартная библиотека с одним ядром | `project.kinii` + cross-file видимость (сделано); `files:` общий код; библ. растит ядро, ядро не растёт |
| **TypeScript / JS** | вывод типов; строгие типы там, где автор указал | `let x = 5` — тип выведется; `let u32 x = ...` — явный контракт (сделано) |
| **JS** | функции и лямбды как значения; `async/await/spawn` | `async fn` разбирается и пока работает как обычная функция (бэкен-честно); `[x for x in xs if ...]` — компехензия вместо LINQ/map-filter |
| **Python** | понятность; один честный способ сделать одну вещь | `decide/weight` — прямая развилка, вместо цепочек тернарников; простой `print`; списки как литералы |
| **Lua** | маленький язык, лёгкий рантайм | ~30 ключевых слов; рантайм = пара функций `kn::` в сгенерированном C++; одна сборка без церемоний |
| **Swift** | безопасность и честные ошибки; именованные аргументы | диагностики «понятно даже дурному» (K0xxx–K3xxx, сделано); `Point { x: 1, y: 2 }` (сделано); null в языке нет |
| **Linux (ядерная модель потоков)** | изоляция и планировщик без магии | `isolate`/`node` = отдельный поток: инструкции тела становятся задачей, стартующей вместе с `app_entry`; программа всегда дожидается своих задач (`join` в конце `main`); функции узла видны всему проекту |
| **Shell** | пайплайны данных | `xs |> sort |> print` — оператор `|>` (сделано: `a \|> f(b)` = `f(a, b)`, вызов обязателен справа — K1006) |

Явно НЕ берём: GC (детерминированные значения и зоны вместо), макроязык препроцессора («лишние слои между кодом и смыслом» — этим правит `kin::define`... нет: без макросов_INIT), исключения как управление потоком (ошибки — через returns и decide), динамическую типизацию (только аннотации), ООП с наследованием (структуры + интерфейсы, композиция).


## Что убрано из VOID-Core v2.0

| Убрано | Причина |
|---|---|
| `zeroize`, `move` со стиранием памяти | усложнение; копиями управляет оптимизатор |
| `cell:ghost / fwr / sec` | «защитная магия», не влияет на размер и понятность |
| `&-` мост | заменён обычным `import` и вызовами |
| стелс-функции (`unlink_peb`, `raw_inject`, `fake_panic`) | не часть языка |

## 3. Переменные

```
let x = 5;                        // тип выводится сам
let u32 count = 50;               // явный тип
let u32[1024] bitmap;             // массив фиксированной длины
let list<string> packs = ["a"];   // динамический список
let map<string, u32> prices = ["хлеб": 50];   // словарь: ключи/значения проверяются честно
let name: ptr = 0x11000000;       // тип после имени — тоже можно
const MAX_RETRY = 3;              // константа (обязательно со значением)
```

## 4. Функции, структуры, перечисления

```
fn add(a: u32, b: u32) -> u32 { return a + b; }

pub fn verify() -> bool { ... }     // pub/priv — видимость
async fn poll() { ... }             // асинхронность
entry boot() { ... }                // точка входа
handler on_input(event: ptr) { ... }// обработчик прерывания

struct VarDecl {
    type: string;
    is_constant: bool;
}

enum DataType { U8, U16, U32, U64 }
```

**Имена** (переменные, функции, структуры, поля, перечисления): латиница
(`a-z`, `A-Z`, `_`, цифры не первым символом) **и кириллица** (`а-я`, `А-Я`,
`ё`, `Ё`) — язык понятный, имена читаются по-русски:

```
fn двойня(х: u32) -> u32 { return х * 2; }
struct Точка { х: u32; у: u32; }
let сломано = 21;
```

Ключевые слова — только латиницей (`fn`, `let`, `struct`, `while`, ...);
«функция» или «если» как ключевые слова не работают — и честно попадают
в K2002 «неизвестное имя».

## 5. Контейнеры верхнего уровня

```
node MemoryCore { ... }          // узел: функции видны всему проекту; инструкции тела — отдельный поток
isolate Cleaner { ... }          // то же, без намёка на «системность»; чистая задача
app_entry { ... }                // вход приложения (ровно один на проект)
page Dashboard { render() { ... } }  // UI-страница (.web)
```

Как node/isolate живут в бэкенде:
- функции внутри узла поднимаются на уровень проекта (как и семантика);
- инструкции тела узла становятся задачей `kn_iso_body_N`;
- все задачи стартуют вместе с `app_entry`, перед `main`-тело;
- `main` всегда дожидается задач: `kn_iso_body_N_t.join()` — приложение не
  завершится раньше своих узлов.

## 6. Управление потоком

```
if (x > 0) { ... } else if (x == 0) { ... } else { ... }
while (cond) { ... }
loop { ... }
for item in items { ... }         // перебор списка: item — элемент
for pair in словарь { ... }       // перебор словаря: pair.key и pair.value
return value;

decide (status) {                 // ветвление (генерируется как цепочка if/else)
    weight("SELECT") => { ... }   // работает и по строкам, не только по числам
    else              => { ... }
}
```

- Переменная `for` по списку — элемент списка; по словарю — запись с ровно
  двумя полями: `.key` (ключ) и `.value` (значение), чужое поле — K2007.
- `pair.value` можно менять — запись в словарь:
  `for pair in m { if (pair.value < 30) { pair.value = 25; } }`.

- `break` выходит из ближайшего цикла — даже внутри ветки `decide`: decide —
  это ветвление, а не цикл, ветку он просто выбирает.
- `continue` — только внутри цикла. Оба честно проверяются семантикой
  (K2013/K2014 — «не в цикле»).

## 7. Выражения

```
a + b - c * d / e % f            // арифметика
x == y != z < w >= v && u || t   // сравнения и логика
cond ? a : b                     // тернарник
m["key"], point.x, f(1, 2)       // индексация, поле, вызов
m["key"] = 5                     // запись в словарь: K и V проверяются семантикой
["a", "b"]                       // список
["ключ": 50, "другой": 90]       // словарь — пары «ключ: значение»
Point { x: 1, y: 2 }             // структура
[i for i in items if i != "x"]   // comprehension
m.size                           // число пар; также keys()/values()/contains()/remove()
xs |> f(a)                       // пайплайн: то же, что f(xs, a), читается слева направо
num |> show() |> save("out")     // цепочки: каждый шаг — вызов, значение — первым аргументом
```

## 8. Встроенная библиотека

| Вызов | Что делает |
|---|---|
| `print(a, b, ...)` | печатает аргументы подряд и переводит строку (аргументов любое число) |
| `len(x)` | длина списка/строки |
| `console.print(a, b, ...)` | то же, что print (имя для [SYS]-слоя) |
| `console.read_input()` / `console.read_input("подсказка")` | строка со стандартного ввода; подсказка печатается перед ожиданием |
| `console.read_line()` | то же, без подсказки |
| `sys.exit(code)` | завершить программу с кодом выхода |
| `sys.time.now()` | время в миллисекундах (u64) |
| `sys.rnd.next(n)` | случайное число 0..n-1 |

**Методы словаря** (тип `map<K, V>` обязан быть указан явно — K1014 вырастает в
целое правило языка):

| Вызов | Что делает |
|---|---|
| `m.size` | число пар (можно и `len(m)`) |
| `m.contains(k)` | есть ли ключ `k` в словаре (bool) |
| `m.remove(k)` | убрать пару по ключу |
| `m.keys()` | `list<K>` — все ключи |
| `m.values()` | `list<V>` — все значения |

Всё остальное из `sys.*`/`host.*`/`hw.*` — честная ошибка K3001 с подсказкой:
бэкенд не притворяется, что умеет то, чего нет.

## 9. Профили сборки

Миссия «компилятор не добавляет от себя ни байта» — в двух местах:

1. **Прелюдия по использованию.** Перед печатью прелюдии компилятор сканирует
   проект и включает только то, что реально встретилось в коде: не было
   `print` — нет ни `printf`-ния, ни хедеров; нет словарей — нет
   `<unordered_map>`; нет изолят — нет `<thread>`. Мёртвый код в бинарник
   не попадает, скрытого статического инициала нет.

2. **Профиль tiny** (`kinic build ... --tiny`):
   `-O1 -fno-exceptions -fno-rtti -fno-threadsafe-statics
   -ffunction-sections -fdata-sections -Wl,--gc-sections -s`.
   Обработчик исключений и RTTI-таблицы не включаются (сгенерированный код их
   не использует), линкер выкидывает неиспользуемые секции.
   `-Os/-Oz` не используется: на текущем тулчейне (MinGW gcc 16.1) они ломают
   линковку `std::string`.

Замер (демо-приложения, MinGW gcc 16.1, PE-билд):

| Пример | обычный (-O2) | tiny | выигрыш |
|---|---|---|---|
| pipe_demo | 18,5 КБ | 18,5 КБ | 0% |
| demo | 22,0 КБ | 21,5 КБ | 2% |
| modern | 31,5 КБ | 29,5 КБ | 6% |
| for_map_demo | 26,0 КБ | 23,0 КБ | 12% |
| sem_check | 19,5 КБ | 17,0 КБ | 13% |
| map_demo | 37,0 КБ | 33,5 КБ | 9% |

Пол в ~17 КБ — это CRT и таблица импорта динамической libstdc++; дальше
минус возможно только в freestanding-режиме (без CRT/библиотек) — путь к
«ОС на KINII»: отдельный этап, не часть текущего бэкенда.
