# План разработки KINII/VOID-Core toolchain

Компилятор `kinic` на C++20 (g++/MinGW + CMake + Ninja), VS Code расширение.

| Этап | Что | Статус |
|------|-----|--------|
| 1 | Ядро: токены, лексер с точными координатами, движок диагностик (rustc-style), CLI `kinic lex` | ✅ готово |
| 2 | Парсер + AST, ошибки «понятно даже дурному»: фрагмент с кареткой, подсказки, «как должно выглядеть» | ✅ готово |
| 3 | Семантика: имена с подсказками «может быть, X?» и ссылками «объявлен здесь», типы, аргументы, поля, decide | ✅ готово, включая импорты: драйвер загружает граф файлов (K2009 цикл, K2012 не найден), двухфазный сбор символов, K2011 «есть в другом файле, но не импортирован» с межфайловой заметкой |
| 4 | Оптимизатор с отчётом («что оптимизировал и почему», без потери логики) | ✅ готово: `kinic opt` — свёртка констант (арифметика, сравнения, строки, &&/||, тернарник), if/while/decide по константе (живёт только нужная ветка), мёртвый код (непрочитанные переменные, выражения без эффекта, код после return), совет «импорт не используется»; метрика «узлов AST: до → после» |
| 5 | Кодогенерация | ✅ готово: `kinic build` — проверки → оптимизация → чистый C++20 (`kinic_build/*.cpp`) → `g++ -O2 -s` → компактный exe (demo ≈ 22 КБ); app_entry → int main, decide → switch, comprehension → лямбда, «строка + число» → конкатенация; честные K3001/K3002 для ещё неописанных фич (node/isolate, sys.*) |
| 6 | VS Code расширение: подсветка (tmLanguage), скобки, сниппеты; затем LSP с диагностиками kinic в реальном времени | ✅ готово: грамматика + сниппеты (vscode/kinii/), LSP-сервер `kinic lsp` (JSON-RPC 2.0 поверх stdio, свой мини-JSON, полная синхронизация текста), клиент extension.js без зависимостей; didOpen/didChange → publishDiagnostics с кодами K1xxx/K2xxx, relatedInformation для ошибок конкретного файла; smoke-тест tools/lsp_smoke.ps1 |

## Сборка

```
cmake -S compiler -B compiler/build -G Ninja
cmake --build compiler/build
compiler\build\kinic.exe lex reference\main.vc
```

## Проект (project.kinii — как csproj)

В папке проекта создайте один раз `project.kinii`:

```
// общий код (типы и функции видны всем файлам без import)
files: util.ctos, util2.ctos

// входные точки — по одной exe на каждую
entry: demo.vc
entry: other.vc
```

Дальше команды работают без аргументов (или с путём к папке):

```
kinic check          — проверить весь проект
kinic opt            — оптимизация с отчётом
kinic build          — собрать exe каждый entry
```

Видимость «как в C#»: файлы проекта видят верхнеуровневые объявления друг друга
сами; `import` больше не обязателен (остался для папок вне проекта).
